================================================================================
                      COMMITS DECISION DETAILS
================================================================================

PROBLEM: Commits are created but NEVER used anywhere in the code.

MongoDB Collections:
✓ branches - Created and used for tagging
❌ commits - Created but queries never executed
✓ runs - Actual run data

Current Flow:
1. Run completes
2. Branch created/fetched (OK)
3. Commit created with link to run (POINTLESS)
4. Commit stored (NEVER READ AGAIN)

Industry Research:
- MongoDB Docs: Document versioning for UPDATED documents (not immutable runs)
- Beets: No versioning (simple history)
- FlexGet: No versioning (simple history)
- MediaCMS: No versioning (Django audit fields)

DECISION: ❌ ELIMINATE COMMITS

Solution:
- Keep branches as simple string tags
- Add "branch" field to runs (e.g., "main", "staging")
- Delete commits collection
- Delete ~500 lines of code
- 2-3x faster queries (no JOINs)
- 30% less storage (no duplication)

See COMMITS_DECISION.md for full analysis.
